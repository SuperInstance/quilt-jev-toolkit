# DESIGN — quilt-jev-toolkit (the organ protocol repo)

This file records the design passes the code already embodies, newest first,
with the alternatives that were considered and REJECTED — a rejected
alternative is a lesson someone else doesn't have to re-pay. Protocol
doctrine itself lives in `docs/REVERSE-ACTUALIZED-SPEC.md`.

---

## §4 The chrono-op adapter — `bootChrono` (wave-68, lane 68-a)

**Problem.** 67-a's hand-off: quilt-chrono's seal is byte-exactly an organ
checkpoint and its sidecar links are organ receipts, but the LINKS' ops are
chrono entries (`op.op = "read"|"write"` + fields), which organ's evaluator
(`toyQuilt.applyOp`) cannot apply — so a sealed chrono sheet was verifiable
by the organ but not BOOTABLE by it. Make it bootable without touching
quilt-chrono (read-only reference) and without weakening any organ law.

**Shipped shape.** `src/organ/chronoOps.js`:

- `mapChronoChain(links)` — the bridge. One deterministic pass: each link →
  exactly one organ receipt at the same seq (`read` → the `organ.chrono.read`
  no-op witness; unborn `write` → `init(kind:"value")`; born `write` →
  `set`; a push is chrono's (read,write) flow pair and lands as the
  (witness, transition) pair). Every mapped op embeds `chrono: {seq, hash}`
  (its source link) and no wall-clock. Fail-closed: `CHRONO_OP_UNMAPPABLE`,
  `CHRONO_FLOW_UNPAIRED`.
- `bootChrono({links, checkpoint}, {key})` — the courtroom, in order:
  signature → anchor manifest → sidecar chain verify → boundary pin →
  mapping → mapped-replay == SIGNED state → the REAL `boot()` on the mapped
  bundle. With the seal at the tip the SIGNED manifest is reused verbatim as
  the organ manifest (R8); with post-seal appends the tip is re-snapshotted
  with the same organId and `supersedes` = sealed manifestHash (R10).
  Provenance: `organ.custody = {kind: "chrono-seal", ...}` (R9).

### Alternatives considered

**A. Teach `toyQuilt.applyOp` the chrono entries (the 67-a sketch, taken
literally: "3 functions in toyQuilt.mjs").** Add `read`/`write` cases to the
stand-in evaluator's switch so the raw sidecar links replay directly.
REJECTED: the toy substrate's header pins its own law — a v0 stand-in with a
tiny, closed vocabulary (`init/set/render`) whose job is to disappear when a
real cells/ledger layer lands. Growing it for a foreign substrate makes the
stand-in permanent and couples two repos through the most delicate line in
the protocol (the evaluator the whole replay guarantee rests on). What
shipped instead keeps toyQuilt byte-identical and puts the translation in a
module whose ONLY job is translation. (The 67-a sketch's deeper intent —
adapt `quiltApply/applyOp/stateOf` when a real substrate arrives — is
unchanged; this lane adapted the *third-party* substrate, not the toy.)

**B. Emit pure toy ops and DISCARD the reads (state-only translation).**
Writes → init/set receipts only; reads vanish. REJECTED: the sidecar is
sealed 1:1 — dropping receipts breaks the seq alignment with the sealed
chain, and the read entries are causal evidence (unpaired pulls, throttled
tide attempts are LEGAL chrono entries whose loss would silently rewrite
history). The `organ.*` no-op envelope exists precisely for receipts that
change no cells and must still exist; using it costs nothing and loses
nothing. This is the only alternative that is also *dishonest* rather than
merely worse — which is why it is receipted here.

**C. Vendor/partial-custody boot: carry only receipts [seal+1..tip] + seed +
the signed checkpoint, booting through the existing v2 partial-custody path.**
REJECTED for v1 of the adapter, on a hard technical ground: the v2 courtroom
pins the first carried receipt's parent to the SIGNED chain tip
(`cp.hash === genesis.prevHash`), but the mapped receipt chain has DIFFERENT
hashes than the chrono chain (different ops), so a mapped tail can never pin
to the chrono seal's boundary hash. Making it possible would require the
mapped chain to embed the chrono hashes as its own — i.e. R5 — plus a new
courtroom branch. The full-custody translation shipped instead (the adapter
carries every receipt; replay from GENESIS; the seal proves the SOURCE).
Parked in spec §9.5 with the observation that R5's embedded bindings are the
exact substrate a future O(tail) chrono boot would carve on.

**D. Runtime cross-repo import (`import("../quilt-chrono/src/seal.js")`).**
REJECTED — the 67-a law, kept: equivalence is a TEST, not an import. The
toolkit stays standalone (stdlib-only, no sibling needed); the committed
fixture (`tests/fixtures/chrono-fixture.json`, generated BY chrono's seal via
`scripts/vendor-chrono-fixture.mjs`, provenance in the file) carries the
proof, and the LIVE test runs only when the sibling is present
(skip-if-absent), both directions.

**E. A separate `quilt-organ-chrono` glue repo.** REJECTED: this repo owns
the organ spec; the adapter is spec (§9) plus ~380 lines that import only
local primitives. A third repo would have split the courtroom from the law
it enforces and added a release boundary for zero isolation benefit.

### Honest findings (baked into the design)

1. **Verified-vs-mintable asymmetry.** The chrono sidecar VERIFIES under
   organ `verifyChain` (shared hash formula — 67-a's proven identity) but
   cannot be MINTED by organ `makeReceipt`, which demands `op.type`; chrono
   entries name their verb in `op.op`. The test suite's `chainOf()` must use
   the raw formula — the asymmetry is now a documented, tested boundary
   (spec §9.5), not a surprise waiting for the next lane.
2. **A push births its sink.** The mapping table's R2 composes with R4: a
   pushed write to an unborn cell is an `init` — the fixture's push pair is
   the test (the first test draft asserted `set` there and was corrected by
   the suite — the mapping table, not the code, was wrong).
3. **`foldWrites` vs replay.** The bridge folds state through the MAPPED
   receipts, not the raw entries, so the bridge's fold IS the organ replay by
   construction; boot() re-proves it with the real evaluator. A mapping bug
   cannot hide behind a divergent private fold.

## §3 v2 — checkpoint signatures + partial custody (lane 65-b, summary)

Alternatives considered then, for the record: signing the STATE hash alone
(rejected: without the manifest in the signature, the seed's anchoring is
indirect and the organ identity unbound — the triple `(hash, manifestHash,
seq)` signs exactly what a verifier re-derives); a chrono-specific signature
format on the chrono side (rejected by 67-a: parallel standards start as
convenience); Ed25519 immediately (rejected: key management is a fleet-level
decision; HMAC ships now, the alg field refuses unknowns, so v3 is additive).

## §2 v1 — rewind family (lane 64-a, summary)

Destructive organ rewind with compensating host receipts vs copy-on-write
views (shipped BOTH: bundle form is the pure view, organ form is
destructive); auto-repair of double-entry (refused — report-only, v0 law).

## §1 v0 — snapshot/boot (lane 63-c, summary)

Replay-from-genesis as the only trust root (shipped) vs trust-on-first-boot
(refused: an unanchored prefix is unowned history); canonical JSON vs binary
framing (JSON shipped; binary parked, format-drift law via schemaVersion).
